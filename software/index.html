Getting data out of WinCC archives

You need last quarter’s KPIs for a critical report. Or you need to retrieve last years data for regulatory compliance. Or you need data from an old project, and all you have is a backup folder of .mdf files.

WinCC’s own export options assume a running system and a lot of manual work. Tag logging archives are stored compressed, so plain SQL can’t read them. You need the WinCC OLE DB provider, which is installed with WinCC and with the WinCC Connectivity Pack. Exporting through it from SQL Server Management Studio into Excel is limited and slow, and it’s easy to get the time zones wrong.

Step by step: How to export WinCC tag logging data to CSV.

Why You Need This Tool

Faster with parallel reading

Asks WinCC for 20 tags per request and sends several requests at once. The Parallel setting (1 to 8, default 4) is a single box in the main window, and the output is identical whatever you choose.

Reads archives wherever they are

Point it at a folder of tag logging .mdf files from a running system, a stopped system, or a backup copied from another PC. It processes every file in the folder in one run, so there’s no handling files one by one. All you need is the archive files. You don’t need the WinCC project.

Or pulls from a running project

Gets the newest values, up to now, from the open project’s runtime database. This works over the network, so you can read from another PC’s SQL Server.

One file per tag, or one for all

Predictable file names in a year and month folder, ready for scripts and bulk loads. Or put every tag in a single file. Either way, a new file is started when the row limit you set is reached (up to 1,000,000), so each file still opens in Excel.

Time zones done right

Enter your range in the plant’s time zone. Every row carries both UTC and local time, including daylight-saving changes.

Your layout, your columns

Choose columns, order, delimiter, and timestamp format. Add fixed-text (literal) columns, empty columns, and columns built from part of the tag name, such as a station ID. Start from the “Bulk insert” preset for loading into a database, and save your layout to a file to reuse it on another PC.

Only the tags you want

Export everything, or filter with a tag list that supports wildcards. Import lists from a text or CSV file, and export them to keep a separate list for each job. After the run, any entry that matched no tag is reported, with a “did you mean…?” hint when only the capitalization differs.

Averages, minimums, maximums and more

Instead of every logged value, get one value per interval: average, min, max, first, last, sum or count, for any interval from 1 second to 31 days. Hourly averages or daily maximums for each tag make files a fraction of the size. Each row is stamped with the start of its interval.

The last good value, even when a PLC drops out

Get the last value of each day (or hour, or any interval) that has the quality you want. If a PLC goes offline and the last values of the day are bad, you still get the last value logged while the quality was good. Choose Good only, Uncertain or better or Any quality, based on WinCC’s own quality codes.

Filter by value or quality

For raw values, keep only the rows that pass up to four value tests, such as above 100 and below 200, or that have at least a minimum quality. Filtered files are named separately, so they never mix with your unfiltered exports.

Doesn’t disturb a live system

It only reads. Archives WinCC has attached are read in place and left attached. Before it attaches anything, it warns you if a file would be upgraded by your SQL Server, and the default answer is No.

Stop it when you need to

Cancel On Next DB finishes the archive being read and then stops. Stop Now stops after the current tag without waiting for the archive to finish. Values already written stay in the files.

See what happened

Every run writes ArchiveStats.txt with the values exported per tag and how long each database took. Problems with individual tags go to Errors.txt. Open output folder and View errors buttons take you straight to them.

Clear messages when something’s wrong

Pre-checks for SQL Server, permissions, and the WinCC OLE DB provider before touching any database, with plain advice on what to do.

Parallel reading: big exports in a fraction of the time

WinCC takes a fixed amount of time to answer each request, however little data comes back. So the tool sends fewer, bigger requests (20 tags each, the most WinCC accepts) and keeps several in flight at once. Set Parallel to the number of simultaneous requests you want. The default is 4.

Frequently asked questions

How do I export WinCC tag logging data to CSV or Excel?

Choose a source (a folder of archive .mdf files, or a running WinCC project), set the date range and time zone, and click Process. You get CSV files, one per tag or all tags in one file, that open directly in Excel or import into SQL Server and other databases. WinCC’s own export options assume a running system and a lot of manual work. This tool does it in one run.

How fast is it, and what does Parallel do?

The tool reads 20 tags per request and sends several requests to WinCC at the same time. Parallel sets how many (1 to 8, default 4). On one WinCC 7.4 server, 815 tags took about 8 minutes with Parallel 1, 4 minutes with 2 and 3 minutes with 4. More than 4 helps little. The extra requests add load to WinCC’s SQL Server, so use 1 or 2 on a busy production server. The output is the same whatever the setting.

Does it work with WinCC SCADA and WinCC Professional?

Yes. It supports WinCC SCADA V7.4 through the current version, and WinCC Professional. WinCC Unified is not supported.

Can I get data out of WinCC archive files without WinCC?

Yes. You need the archive files, a PC with SQL Server, and the WinCC OLE DB provider, which is included in the WinCC Connectivity Pack. You don’t need the WinCC project or a WinCC license on that PC.

Does it work without WinCC running?

Yes. Point it at archive .mdf files and it reads them directly through SQL Server. You don’t need the WinCC project, only the archive files, and you point it at the folder rather than at each file. Only the “running project” source needs WinCC open.

Will it affect my running WinCC system?

It only reads data. It never detaches or changes archives that WinCC has attached. Very large exports add load to the SQL Server while they run, so schedule those sensibly.

Does it change my archive files?

No data is changed, but attaching a file to a newer SQL Server version than the one that created it upgrades the file. If the archives must go back into an older system, export from copies.

Where does my data go?

Nowhere. The tool runs on your PC and writes CSV files to a folder you choose. It doesn’t send archive data anywhere. Licenses are checked on the PC and never need an internet connection.

What’s in the CSV?

By default: tag name, UTC timestamp, local timestamp, value, quality code. You can change the columns, order, delimiter, header row, and timestamp format, and save the layout to a file to use on another PC.

Can I export averages, minimums or maximums instead of every value?

Yes. Click Processing… and choose Aggregate: average, min, max, first, last, sum or count, over an interval from 1 second to 31 days. You get one row per interval for each tag, stamped with the start of the interval. An interval with no logged values gives no row.

Can I export the last good value of each day for each tag?

Yes. Choose Last value per interval in the Processing dialog, set the interval to 1 day and the quality to Good only (WinCC quality code 128 and up). If the last values of the day are bad, for example because a PLC went offline, you get the last value logged while the quality was good. A day with no good value gives no row.

Can I export only values above or below a limit, or only good-quality values?

Yes, for raw values. Add up to four value tests, such as above 100 and below 200, and choose a minimum quality. Filtered output goes to separate files with _filtered in the name. A filter can’t be combined with an aggregate.

Why do the two timestamp columns look identical in Excel?

Excel hides the date and hour on times with milliseconds. The data is intact. The User Guide shows the one-line custom format that displays it properly.

Can I export from a WinCC PC over the network?

Yes, with the Running WinCC project source. Enter the other PC’s SQL Server, for example WINCCPC01\WinCC, and you can read its runtime databases from your own PC. You need Windows access to that SQL Server, and the WinCC OLE DB provider must be installed on the PC you run the tool on.

The Archive DB folder source doesn’t work over the network, because SQL Server opens archive files from its own disks. Run the tool on the PC whose SQL Server holds the files, or copy the .mdf and .ldf files to a PC with SQL Server and the WinCC OLE DB provider. For other setups, contact us.

My tag list found nothing. Why?

Tag names are case-sensitive, so temp1 doesn’t match Temp1. After an export, entries that matched no tag are listed, with a “did you mean…?” hint where only the case differs, and saved to UnmatchedTags.txt so you can correct and re-import them. Also check that the tags exist in the archives you exported.

Why did my CSV get duplicate rows?

Files are appended to. If you run the same export twice, or export the same range from both sources, every row appears twice. Use an empty output folder, or delete the old files first. The same applies after you change the CSV layout, because the header is only written when a file is created.

Can I stop an export part way through?

Yes. Cancel On Next DB lets the archive being read finish and then stops. Stop Now stops after the current tag. Any archive the tool attached is detached again.
